# Knowledge base sources

VCSIDE's knowledge base (`data/kb/*.json`) was reviewed on 2026-11-08. Before that, `tia.json`, `riot.json`, `formats.json` and `tv.json` had been written from memory and without sources; `6502.json` is generated by `tools/gen_6502.py`. All descriptions are written in our own words: only facts (addresses, bit masks, sizes, names, cycle counts) were taken from the sources. No text was copied.

Each JSON file has a top-level `sources` array (`id`, `title`, `author`, `url`, `used_for`). Each register, format and TV standard has `sources` (a list of ids) and `verified` (`false` = it contains some claim that could not be confirmed; those claims start with "Unverified" in `issues`). In `6502.json` each instruction has `sources` and `verified`, and there is a top-level `instruction_sources`.

## What was taken from each source

- **Stella Programmer's Guide**: TIA write and read register map, meaning of the bits, HMxx encoding, AUDC table (all 16 values), VBLANK bits, priority and SCORE mode, INPT0-5 input ports, addresses and bits of SWCHA/SWCHB (D7 = P1 difficulty, D6 = P0 difficulty), timer addresses (`$294-$297`), 262/312 lines, 76 cycles per line, the 24-cycle rule after HMOVE, the 8-colour SECAM table.
- **Towers**: 5-colour-clock delay of the players after RESPx (4 on missiles/ball), positions of the NUSIZ copies (16, 32 and 64 pixels), HMOVE extends HBLANK by 8 clocks, late HMOVE at cycle 74 (leftward movement only), RESBL retriggers the ball.
- **6532 datasheet**: A0 = polarity and A1 = IRQ enable in the PA7 edge control (the previous file had it the wrong way round), A3 enables the timer IRQ, the timer expires N·D + 1 cycles later, timer flag cleared on reading or writing the timer, PA7 flag cleared on reading the flags register.
- **masswerk, NMS and Gopher2600 definitions**: bytes, cycles and page penalty of the 256 opcodes (all three agree), stable/unstable classification. The only change: LAS is stable (only SHA, SHX, SHY, SHS/TAS, ANE and LXA are unstable).
- **DASM**: every opcode was assembled to check the name and the bytes. 36 opcodes cannot be generated with a mnemonic (marked `"dasm": false`; `.byte` must be used): the 12 JAMs, the USBC `$EB`, `$2B` (ANC), the 1-byte NOPs and several NOPs with an operand. DASM does not accept `ASL A` with an operand (you have to write `ASL`); the DASM name for `$4B` is `ASR`, not `ALR`.
- **Stella (code)**: cartridge type names for `-bs`, supported sizes, hotspots of FA, FA2, UA, 0840, SB, X07, EF, DF, BF, E0, E7, 3E, 3E+, CDF, DPC+, BUS, detection by strings and by size, Superchip detection, reading the SC write port = unwanted write, RIOT decoding (`M6532.cxx`).
- **United Carts of Atari (PlusCart and UnoCart firmware, https://github.com/Al-Nafuur/United-Carts-of-Atari, v2.3.32)**: the ELF loader's 96 KB RAM buffer and 64 KB of CCM RAM (`main.h`), files bigger than the buffer written to flash with only the code, writable data and read-only data with relocations copied to RAM, zeroed variables in CCM RAM (`cartridge_emulation_ELF.c`, `elfLib.c`). Used by the ELF space report.
- **Gopher2600 (code)**: accepted `-mapping` ids (`cartridge.go`: F0, 0840, X07, 4A50 and BUS do not exist), fingerprint of ELF/CDF/DPC+/3E+/AR/SC, CDF and E7 hotspot table, vcsLib names of the ELF loader, line counts per TV specification.
- **Tests with the Gopher2600 binary** (our own test programs): RESP0 position = 3·N − 68 + 5 (N = write cycle; N = 23 gives 6), RESM0/RESBL = 3·N − 68 + 4, in HBLANK without HMOVE the player ends up at 3 and the missile/ball at 2; WSYNC written at cycles 72, 74 or 75 resumes at cycle 0 of the next line, and written at cycle 0 it waits a whole line.

## Music editor (0.2.0): techniques and their authors

Read for the design in `docs/design-music.md`; only facts are taken, in our own words, and no code. The editor's help credits the same people next to each feature.

- **VCSIDE's music player** (`src/music/export.cpp`, the 6502 code in the export): written for VCSIDE from the editor's own rules, with no other player's code; CC0, like the templates. Sound effects that take a music channel while they sound are common in 2600 games; who did it first is still to be found. Sound effects on the TIA's free channel while the cartridge's voices play on the other are done in DPC+ and CDFJ games; who did it first is still to be found too.
- **Ultimate Soundtracker** (Karsten Obarski, Amiga, 1987; https://en.wikipedia.org/wiki/Ultimate_Soundtracker): the tracker layout the music editor follows, with patterns, an order list and a per-cell effect column (in VCSIDE, V and R pick an instrument's volume and release variants).
- **TIATracker** (Andre "Kylearan" Wichmann, 2016-2017, https://bitbucket.org/kylearan/tiatracker; licences from Debian's copyright file: program GPL-2.0-or-later, player Apache-2.0): instruments with per-frame envelopes, swing, the `.ttt` format to import. The format and how songs play were read in the source of a GitHub copy (https://github.com/dionoid/tiatracker: `track/*.cpp`, `emulation/player.cpp`, `player/dasm/tt_player.asm`); no code was taken. Facts used: 7 instruments (AUDC, per-frame AUDF offsets and volumes, sustain loop from `sustainStart` to `releaseStart` - 1, release played once) and 15 percussion sounds (AUDC, AUDF and volume per frame, played once); note types 0 hold, 1 instrument (the value is an AUDF; 0-63 for the "pure combined" waveform, AUDC 4 below 32 and 12 above), 2 pause, 3 percussion, 4 slide; waveforms 5, 9, 10, 13 sound as 4, 7, 6, 12 and 11 is silent; a sequence per channel with jumps, and playback stops when a channel without a jump runs out; a row lasts `oddspeed` frames when its index in channel 0's pattern is even and `evenspeed` when it is odd (both players count the row after it), from the song or, without global speed, from channel 0's pattern.
- **Paul Slocum, *Atari 2600 Music and Sound Programming Guide*** (v1.02, 2003, https://www.qotile.net/files/2600_music_guide.txt): the three non-tempered setups, tuning against the song.
- **Eckhard Stolberg, frequency and waveform guide** (referenced by Slocum's guide): the tuning of every TIA note.
- **Ron Fries, TIASOUND** (1996, LGPL-2): the frequency formula and the bit patterns of the distortions.
- **pizzatari, TIA Music Explorer** (https://pizzatari.github.io/TiaMusicExplorer/): A4 and transposition settings against TIA pitches.
- **Aleksi Eeben, Star Bars** (2023, https://forums.atariage.com/topic/353597-star-bars/): Tiatonic Tuning, fractional frequency bits as 8-bit patterns applied every 8 or 16 scanlines.
- **Natt (AYCE), TIunA** (2024, MIT, https://github.com/AYCEdemo/twin-tiuna): finer pitch by switching between two AUDF values.
- **utz, TIAtune** (2017, updated with Thomas Jentzsch in 2022, MIT, https://github.com/utz82/tiatune): software dividers, 16-bit, pitch within 0.15 %, using all the CPU time.
- **Chris Brenner, "TIA Sounding Off in the Digital Domain"** (AtariAge topic 249865), credited in Gopher2600's `hardware/tia/audio` (GPL-3), which implements it like Stella (`Audio.cxx`, `AudioChannel.cxx`, GPL-2) and 6502.ts (MIT): the TIA's audio at the counter level (5-bit divider, 5-bit noise register, 4-bit pulse register, two phases per audio clock) and the mixing of both channels, out = sum/30 × 60/(30 + sum), in Thomas Jentzsch's simplification. VCSIDE's `src/music/tia_audio.cpp` is written from that description; its test compares 64 AUDC/AUDF cases with hashes of Gopher2600's output (commit 07d8de5), generated with a small Go program that is not kept. The counters give AUDC 15 a period of 93 audio clocks, not TIASOUND's 186.
- **ELF samples** (`src/music/player.cpp`, `SampleMixer`, and the C player in `src/music/export.cpp`): written for VCSIDE. Direct digital synthesis (a phase accumulator per voice) is a general technique with no single author. The overblank program that plays a nibble per line from $E0-$FE to $2D is the ELF loaders' own (United Carts of Atari firmware, Stella's `VcsLib.cxx`, Gopher2600's `strongarm_vcslib.go`); the bytes at $86-$87 ("sta $2d") are checked before they are changed, so another loader's program is left alone. Who first played 4-bit samples through AUDV is still to be found (see below).
- **DPC+ and CDFJ music** (https://forums.atariage.com/topic/345456-cdfj-audiowaveformsenvelopes/): 3 voices with 32-sample waveforms in RAM, aligned to 32 bytes, the amplitude copied to AUDV0 every scanline; CDF and CDFJ reuse the DPC+ music routines (the Mappy driver is a port of Stay Frosty 2's).
- **DPC+ export** (`src/music/export.cpp`): the registers and the ROM layout were read in batari Basic's DPC+ files (CC0: `DPCplus.h`, `DPCplusheader.asm`, `DPCplusfooter.asm`, `DPC_frequencies.h`, and a program compiled with them): `AMPLITUDE` read at $1005; `WAVEFORM0-2` at $105D-$105F, a 32-byte slot of the 4 KB display data (address & $1FFF divided by 32); `NOTE0-2` at $1075-$1077, an index into the 1 KB table of 256 32-bit frequencies that follows the display data, each 2^32 x Hz / 20000; the driver's 3 KB, six 4 KB banks, the display data and the table, 32 KB in all; the first 128 bytes of every bank are hidden by the registers; Stella starts the cartridge in the last bank. The sum of the voices goes to AUDV0 with no volume per voice. No batari Basic code is in VCSIDE; the test ROM uses its CC0 driver, from the batari Basic that VCSIDE installs, and is not shipped.
- **DPC+ example** (`data/templates/dasm-dpcplus`): VCSIDE does not carry DPC+'s ARM driver; a new project gets a copy of `DPCplus.arm` from the batari Basic that VCSIDE installs. batari Basic's licence makes its included 6507 assembly CC0 but does not name the driver binary, so it is not redistributed until that is known: still to be found. Facts used besides those above: a reset in any bank must reach the program, so each bank selects bank 5 at the same address ($1FFB) and jumps. Stella measured: with AMPLITUDE copied only on the kernel's lines, 9 lines a frame went without sound while the player and the game logic ran; the player now copies it at the start of each of its routines and the example between its calls, and no gap is longer than 2 lines.
- **CDFJ export**: the ARM code calls the driver's `setNote`, `setWaveform`, `resetWave` (as described in the AtariAge thread above); VCSIDE only calls hooks the game defines, so it does not depend on any driver's headers.
- **CDFJ example** (`data/templates/dasm-cdfj`): CDFJ by Chris Walton, Fred Quimby and Darrell Spice Jr. (the copyright line of the CDFJ headers); SpiceWare's tutorial (https://forums.atariage.com/topic/297759-part-1-cdfj-overview/) describes it. Its driver is not included: the tutorial's attachment (`Collect3_20191215.zip`) was no longer on AtariAge on 2026-11-10, and no licence for the driver or the framework was found, so VCSIDE carries neither (still to be found); the project's Makefile asks for `cdfj_driver.bin`. The 6507 program, the C code, the entry code, the linker script and the division are our own. Facts used, checked in Stella 7.0's `CartCDF.cxx` and `Thumbulator.cxx` and in the framework's headers (copy in https://github.com/JetSetIlly/plusromtest_cdfj, read, not copied): registers at $1FF0-$1FF3 (DSWRITE, DSPTR written high byte then low byte, SETMODE with $F0 = fast fetch and music mode, CALLFN with $FE = run the ARM code with the sound kept going); banks 0-6 at $1FF5-$1FFB and the 6507 starting in bank 6; fast fetch replaces the operand of `lda #` from 0 to $23 with a data stream (DSCOMM = $20, AMPLITUDE = $23); the C code at $0800 entered in ARM state and run from $0808 in Thumb; Harmony's RAM at $40000000: the driver's 2 KB, the display data from $40000800, 2 KB free from $40001800, the stack below $40001FFC; data stream pointers at $40000098 (offset << 20) and increments at $40000124 (whole << 8 | fraction); voice waveform addresses at $400001B0; the driver's functions at $0751 (setNote), $0755 (resetWave), $0759 (getWavePtr) and $075D (setWaveSize), with the voice in r2, the value in r3 and the return address set with `mov lr, pc`; frequencies 2^32 x Hz / 20000, as in DPC+; 32-sample waves with size 27. Stella's ARM emulator runs only Thumb code: libgcc's division for the ARM7 is ARM code, so the example has its own. Stella measured: the CALLFN keeps the sound gap at 2 lines (3 when PosObject crosses into the next line, near the right edge).

## Project templates: the DASM game (2026-11-11)

`data/templates/dasm-game` (CC0) is written for VCSIDE, with no other game's code. The techniques it uses and where they come from:

- **48-pixel text** ("THE GAME" on the title screen): both players with three close copies (NUSIZ = 3), VDELP0/VDELP1 on, the players 8 clocks apart, and the last four writes of each line timed to the beam. It is the technique of Activision's six-digit scores in the early 1980s; who devised it first is still to be found. Timing measured in Gopher2600 (writes at cycles 44, 47, 50 and 53 with the players on pixels 55 and 63, which centres the 47-pixel text).
- **The TV system menu** (PLAY and TV rows; NTSC 262 lines, PAL60 262 lines with PAL colours, PAL 312 lines) from La Abadía del Crimen 2600.
- **The NTSC→PAL colour table** (`NtscToPal`, 128 bytes: one PAL colour for each NTSC one): computed for VCSIDE as the nearest colour by CIELAB distance (CIE 1976 ΔE) between Stella's NTSC and PAL palettes, as Gopher2600 lists them (`hardware/television/colourgen/legacy.go`; the values only, which are facts). The palettes are Stella's (with Thomas Jentzsch's updates). A table of hues alone (luminance kept) was tried first: it turned NTSC orange $2A into a PAL yellow and the room's colour into brown. Most matches are within ΔE 10; PAL has nothing close to the brightest NTSC yellows ($1E→$2C, ΔE about 30). The cartridge's row colours go through the same table into RAM, shared with the game's state.
- **Flicker**: the two enemies share player 1 and take turns, one per frame (30 Hz each); a general technique of 2600 games, with no single author. When one is left it is drawn on every frame (no flicker), and it still moves on every other frame, at the same speed.
- **Hardware collisions** (CXP0FB, CXP1FB, CXM0FB, CXM0P, CXPPMM, cleared with CXCLR) to stop the hero and turn the enemies: the Stella Programmer's Guide. The TIA does not say which side touched, so an enemy turns one axis chosen by an 8-bit Galois LFSR (taps $B4, a general technique); a fixed rule was measured to trap them in a loop.
- **The title's cartridge**: drawn after VCSIDE's own icon (`assets/icon`, its 5x7 VCS and 3/4x5 IDE letters); an **asymmetric playfield** (PF0-PF2 written again in mid-line) with a colour per row, and the two missiles as the label's sides, since a playfield line has one colour. The menu's texts use the same asymmetric playfield, and the score and lives the **score mode** (CTRLPF = 2): the Stella Programmer's Guide and Towers' notes; the cycles measured in Gopher2600.
- **PosObject** (dividing by 15 in a loop for the coarse position, then HMxx for the rest): the routine most 2600 programs use, as in the `dasm-animation` template; who wrote it first is still to be found.
- **The frame's timing** with the RIOT timer (TIM64T and INTIM) for the vertical blank and overscan: the Stella Programmer's Guide and the 6532 datasheet. Measured in Gopher2600 in the three systems: 262, 262 and 312 lines, stable, on the title screen and in the game.

## Project templates: the banked DASM skeleton (2026-11-12)

`data/templates/dasm-banked` (CC0, F8, F6 and F4) is written for VCSIDE. What it uses and where it comes from:

- **The hotspots** ($1FF8-$1FF9 for F8, $1FF6-$1FF9 for F6, $1FF4-$1FFB for F4; any access switches): the knowledge base's `formats.json`, with its sources (`horton`, `stella-src`, `gopher-src`).
- **Starting in any bank**: the same code at the end of every bank (the vectors point to a switch to bank 0 and a jump to `Reset`), since the bank the console starts in is not fixed; a general technique of banked 2600 games, with no single author.
- **Calling another bank through a trampoline at the same address in both banks** (the switch, then the next instruction fetched from the other bank): a general technique of banked games since Atari's own F8 cartridges; the addresses and the check that each bank's code ends before it are VCSIDE's. Built and run in Stella in NTSC and PAL.
- **batari Basic's `set romsize`, `bank` and `goto ... bankN`**: batari Basic's manual and its `samples` (`64kbb.bas`).

## Main errors fixed

1. **WSYNC at cycle 75**: the note said the wait was "very short"; in fact the wait still ends at the start of the next line (the stall is less than a cycle) and only a write at cycle 0 waits a full line.
2. **Missiles and NUSIZ**: the file said missiles are *not* replicated with the player copies; the guide says the opposite (they share the same decoders).
3. **RIOT, PA7 edge control**: A0 is the polarity and A1 the enable (it was the wrong way round). The timer expires N·D + 1 cycles later (datasheet data), and the timer flag is only cleared by reading INTIM or writing a timer.
4. **PHP on the stack**: "writes several TIA registers in 3 cycles" was false; it writes one, and the value is P (bit 1 is Z, hence the ENAM0/ENAM1/ENABL trick).
5. **LAS** was classified as unstable; it is stable. **BRK** becomes 1 byte (DASM emits only `$00`). **JAM** remains marked as unstable to be safe (it hangs the CPU), with `hangs: true`.
6. **Formats**: 3E+ supports up to 64 KB of ROM and 32 KB of RAM (not 512 KB); E7 has 2 KB of RAM (not 1 KB) and the 256-byte block selector is `$1FE8-$1FEB`; Superchip detection compares the first 128 bytes with the next 128 bytes of each bank (not "all equal"); F0/MB, 0840, X07, 4A50 and BUS do **not** exist in Gopher2600; Gopher's id for F8SC is `F8SC` (not `F8S`); CDFJ and CDFJ+ are the same `CDF` type in Stella; FA2 supports 24-32 KB; BF and CV entries added.
7. **INPT/CX entries**: unsourced claims removed ("380 scanlines", 7800, "off-screen objects do not collide").

- `tia.json`: 59 registers with `sources`/`verified`; notes rewritten (16); about 40 registers with description or `issues` corrected; 22 with `verified: false`.

## Facts that remain unverified

- Position of an object reset during HBLANK (the guide says "left edge"; Gopher2600 uses 3 for players and 2 for missiles/ball; not measured on real hardware) and how it varies with HMOVE and the TIA revision.
- Exact effect of a late HMOVE at cycles other than 74, and HMOVE in the middle of a visible line.
- RSYNC: exact delay and its effect on the RESxx strobes.
- NUSIZ changes mid-line and additional delays of the double and quadruple players.
- Rewrite windows of PF0/PF1/PF2 mid-line (derived from pixel positions, not measured).
- Charge delay of the INPT0-3 pins (full sweep of a paddle) and behaviour of the undriven bits of the read registers.
- AUDV: whether the change applies instantly or on the next audio clock (used for PCM samples).
- Behaviour of INTIM read exactly on the cycle it wraps around (0 → `$FF`), and "idiomatic" TIM64T values (43, 35/36).
- Doubtful formats: FA (Stella's comment says D0 must be 1; the code has it commented out), FA2 (number of banks per variant), BUS (seven banks according to the comment, six hotspots in the code), DF/DFSC (Gopher2600 has no id of its own), CV (title/layout only according to Stella), 4A50 (exact hotspot addresses), F8 (real boot bank).
- ELF: which vcsLib symbols PlusCart firmware 2.3.32 lacks, old Gopher2600 versions with code in RAM and the Chameleon sizes comes from the project's notes, not from a public source.
- Music credits not yet checked in a primary source: the TIA's sound designed by Jay Miner and Joe Decuir; DPC+ by Darrell Spice Jr. and Fred Quimby; DPC by David Crane for Pitfall II. Not found yet: who first played 4-bit samples by writing AUDV with AUDC = 0. Brenner's document itself could not be read (AtariAge was down on 2026-11-09): its credit comes from Gopher2600's source. SECAM consoles' audio clock is taken as PAL's without checking.
- PAL colours: hues 0, 1, 14 and 15 as greys (not checked in a primary document).
- MCS6500 (6 MB datasheet) and Bruce Clark's decimal mode tutorial were not read in this pass.
- Version 0.96 of *No More Secrets* could not be downloaded; 0.91 was used.

## Sources with doubtful licences

All the documentary sources (Stella Programmer's Guide, Towers' notes, 6532 datasheet, MCS6500, NMS, Horton, masswerk) lack an explicit licence in the copies consulted; they were used only to extract facts and have always been rewritten in our own words. Stella (GPL-2), Gopher2600 (GPL-3) and DASM (GPL-2+) were consulted or run without copying text or code.

## ACE cartridges (read 2026-11-10)

Read for the proposal in [design-ace.md](design-ace.md), which lists every source with its author; only facts were taken (header fields, offsets, register addresses, the argument block), in our own words, and no code. The proof of concept in `tools/ace_poc` (CC0) was written from those facts.

- **ACE itself**: ZackAttack (Zack Scolaro), UnoCart firmware, 2018 (`ace2600.h` in Strong-ARM-for-VCS: the header struct); the UF00/PC00/UC00 variants and the argument block at `0x20000000`: Marco Johannes, United Carts of Atari firmware, 2021.
- **Gopher2600's ACE mapper** (JetSetIlly, v0.20.0 and later; local copy `07d8de5`): how it emulates the bus, the PlusCart register addresses, the ELF and DPC+ wrapped in ACE, the debugging ELF names. Our own measurements: the proof of concept runs (342 frames in 3 s), Wolf3D does not produce frames (cause not found yet).
- **Stella 7.0**: no ACE support (none in its source, none in the binary's strings).
- **UCA firmware, read again for phase 2** (`cartridge_emulation_ACE.c`, `cartridge_io.c`, `cartridge_io.h`, read on GitHub, not downloaded): where each kind of ACE file is copied, how the entry is adjusted, and the register pointers per cart (UnoCart: the high byte of GPIOE). Our own measurements in Gopher2600 `07d8de5`: the proof of concept's picture (macro `SCREENSHOT`), its debug ELF read only with DWARF 4 and at the address it runs, and the cause of Wolf3D's failure (SRAM sized by file size, `FLASH->ACR` not mapped).
- **ACE template (phase 3, 2026-11-11)**: the start code, the bus library (`ace_*`), the 6507 takeover with `BIT $24` and the overblank program are our own, written from the facts above. Running the overblank from the 6507's RAM while the ARM works comes from ZackAttack's Strong-ARM framework (`StartOverblank` in its `vcsLib.c`), which the ELF loaders took too; the template's program keeps the ELF loaders' layout (samples at `$E0`-`$FE`, 63 lines) so VCSIDE's C music player works unchanged. From the UCA firmware (read, not copied): calling `reboot_into_cartridge` before using the SRAM buffer, which the firmware fills with its menu while the console reboots; waiting for the same address twice before answering; and sampling the data bus until the address changes on a write. Our own measurements in Gopher2600 `07d8de5`: pictures, frame counts, a WAV recording with 16 levels, the debugger's source listing, and that GCC's `DW_OP_GNU_entry_value` makes it reject the DWARF unless `-gstrict-dwarf` is given.
- **ACE space report (phase 4, 2026-11-11)**: from the UCA firmware (`cartridge_emulation_ACE.c`, `main.h`, `flash.h`, read on GitHub, not downloaded): the 896 KB size check, the download area from flash sector 5 shared with the PlusCart's offline ROMs, the 96 KB buffer, and that `ACE-UF00` is handled the same on both carts. From Gopher2600 `07d8de5` (`hardware/memory/cartridge/ace/memory.go`): the SRAM it gives by file size.
- **`make ace` for ELF games (phase 5, 2026-11-11)**: `vcslib_ace.c` implements the vcsLib interface (names and arguments as in the `elf-template` row above, which go back to ZackAttack's Strong-ARM `vcsLib.c`) on VCSIDE's own ACE bus library; the code is our own. Our own measurements in Gopher2600 `07d8de5`: both ELF templates built as ACE, pictures, frames, WAV recording and debugger.
- **Serving ROMs to the PlusCart (phase 6, 2026-11-11)**: the PlusStore API as the UCA firmware uses it (`esp8266.c`: the request and its headers, the menu's status and entry lines, the range requests and `MAX_RANGE_SIZE`; `main.c`: paths, percent-encoding, the top menu and the downloads; `global.h`: the entry types and the default host; `cartridge_firmware.c`: the account flag), read on GitHub, not downloaded. The firmware's network code is by Wolfgang Stubig (`esp8266.c`'s header), within the United Carts of Atari firmware. The server is our own code.
