# Knowledge base sources

VCSIDE's knowledge base (`data/kb/*.json`) was reviewed on 2026-11-08. Before that, `tia.json`, `riot.json`, `formats.json` and `tv.json` had been written from memory and without sources; `6502.json` is generated by `tools/gen_6502.py`. All descriptions are written in our own words: only facts (addresses, bit masks, sizes, names, cycle counts) were taken from the sources. No text was copied.

Each JSON file has a top-level `sources` array (`id`, `title`, `author`, `url`, `used_for`). Each register, format and TV standard has `sources` (a list of ids) and `verified` (`false` = it contains some claim that could not be confirmed; those claims start with "Unverified" in `issues`). In `6502.json` each instruction has `sources` and `verified`, and there is a top-level `instruction_sources`.

## What was taken from each source

- **Stella Programmer's Guide**: TIA write and read register map, meaning of the bits, HMxx encoding, AUDC table (all 16 values), VBLANK bits, priority and SCORE mode, INPT0-5 input ports, addresses and bits of SWCHA/SWCHB (D7 = P1 difficulty, D6 = P0 difficulty), timer addresses (`$294-$297`), 262/312 lines, 76 cycles per line, the 24-cycle rule after HMOVE, the 8-colour SECAM table.
- **Towers**: 5-colour-clock delay of the players after RESPx (4 on missiles/ball), positions of the NUSIZ copies (16, 32 and 64 pixels), HMOVE extends HBLANK by 8 clocks, late HMOVE at cycle 74 (leftward movement only), RESBL retriggers the ball.
- **6532 datasheet**: A0 = polarity and A1 = IRQ enable in the PA7 edge control (the previous file had it the wrong way round), A3 enables the timer IRQ, the timer expires N·D + 1 cycles later, timer flag cleared on reading or writing the timer, PA7 flag cleared on reading the flags register.
- **masswerk, NMS and Gopher2600 definitions**: bytes, cycles and page penalty of the 256 opcodes (all three agree), stable/unstable classification. The only change: LAS is stable (only SHA, SHX, SHY, SHS/TAS, ANE and LXA are unstable).
- **DASM**: every opcode was assembled to check the name and the bytes. 36 opcodes cannot be generated with a mnemonic (marked `"dasm": false`; `.byte` must be used): the 12 JAMs, the USBC `$EB`, `$2B` (ANC), the 1-byte NOPs and several NOPs with an operand. DASM does not accept `ASL A` with an operand (you have to write `ASL`); the DASM name for `$4B` is `ASR`, not `ALR`.
- **Stella (code)**: cartridge type names for `-bs`, supported sizes, hotspots of FA, FA2, UA, 0840, SB, X07, EF, DF, BF, E0, E7, 3E, 3E+, CDF, DPC+, BUS, detection by strings and by size, Superchip detection, reading the SC write port = unwanted write, RIOT decoding (`M6532.cxx`).
- **Gopher2600 (code)**: accepted `-mapping` ids (`cartridge.go`: F0, 0840, X07, 4A50 and BUS do not exist), fingerprint of ELF/CDF/DPC+/3E+/AR/SC, CDF and E7 hotspot table, vcsLib names of the ELF loader, line counts per TV specification.
- **Tests with the Gopher2600 binary** (our own test programs): RESP0 position = 3·N − 68 + 5 (N = write cycle; N = 23 gives 6), RESM0/RESBL = 3·N − 68 + 4, in HBLANK without HMOVE the player ends up at 3 and the missile/ball at 2; WSYNC written at cycles 72, 74 or 75 resumes at cycle 0 of the next line, and written at cycle 0 it waits a whole line.

## Main errors fixed

1. **WSYNC at cycle 75**: the note said the wait was "very short"; in fact the wait still ends at the start of the next line (the stall is less than a cycle) and only a write at cycle 0 waits a full line.
2. **Missiles and NUSIZ**: the file said missiles are *not* replicated with the player copies; the guide says the opposite (they share the same decoders).
3. **RIOT, PA7 edge control**: A0 is the polarity and A1 the enable (it was the wrong way round). The timer expires N·D + 1 cycles later (datasheet data), and the timer flag is only cleared by reading INTIM or writing a timer.
4. **PHP on the stack**: "writes several TIA registers in 3 cycles" was false; it writes one, and the value is P (bit 1 is Z, hence the ENAM0/ENAM1/ENABL trick).
5. **LAS** was classified as unstable; it is stable. **BRK** becomes 1 byte (DASM emits only `$00`). **JAM** remains marked as unstable to be safe (it hangs the CPU), with `hangs: true`.
6. **Formats**: 3E+ supports up to 64 KB of ROM and 32 KB of RAM (not 512 KB); E7 has 2 KB of RAM (not 1 KB) and the 256-byte block selector is `$1FE8-$1FEB`; Superchip detection compares the first 128 bytes with the next 128 bytes of each bank (not "all equal"); F0/MB, 0840, X07, 4A50 and BUS do **not** exist in Gopher2600; Gopher's id for F8SC is `F8SC` (not `F8S`); CDFJ and CDFJ+ are the same `CDF` type in Stella; FA2 supports 24-32 KB; BF and CV entries added.
7. **INPT/CX entries**: unsourced claims removed ("380 scanlines", 7800, "off-screen objects do not collide").

## Changes in numbers

- `6502.json`: 256 opcodes checked against 3 sources; 77 instructions with `sources`/`verified`; 1 byte size corrected (BRK), 1 classification corrected (LAS); 36 opcodes marked `dasm: false`; ~25 descriptions rewritten.
- `tia.json`: 59 registers with `sources`/`verified`; notes rewritten (16); about 40 registers with description or `issues` corrected; 22 with `verified: false`.
- `riot.json`: 12 registers; notes rewritten; ~10 with corrected texts; 1 with `verified: false` (`TIM64T`, idiomatic values).
- `formats.json`: 34 formats (32 + BF + CV); almost all with rewritten text; 8 with `verified: false`; SC templates corrected (the first 256 bytes of each bank are reserved).
- `tv.json`: 4 standards; notes rewritten; only PAL with `verified: false` (grey hues 0, 1, 14, 15).

## Facts that remain unverified

- Position of an object reset during HBLANK (the guide says "left edge"; Gopher2600 uses 3 for players and 2 for missiles/ball; not measured on real hardware) and how it varies with HMOVE and the TIA revision.
- Exact effect of a late HMOVE at cycles other than 74, and HMOVE in the middle of a visible line.
- RSYNC: exact delay and its effect on the RESxx strobes.
- NUSIZ changes mid-line and additional delays of the double and quadruple players.
- Rewrite windows of PF0/PF1/PF2 mid-line (derived from pixel positions, not measured).
- Charge delay of the INPT0-3 pins (full sweep of a paddle) and behaviour of the undriven bits of the read registers.
- AUDV: whether the change applies instantly or on the next audio clock (used for PCM samples).
- Behaviour of INTIM read exactly on the cycle it wraps around (0 → `$FF`), and "idiomatic" TIM64T values (43, 35/36).
- Doubtful formats: FA (Stella's comment says D0 must be 1; the code has it commented out), FA2 (number of banks per variant), BUS (seven banks according to the comment, six hotspots in the code), DF/DFSC (Gopher2600 has no id of its own), CV (title/layout only according to Stella), 4A50 (exact hotspot addresses), F8 (real boot bank).
- ELF: what is said about PlusCart firmware 2.3.32, old Gopher2600 versions with code in RAM and the Chameleon sizes comes from the project's notes, not from a public source.
- PAL colours: hues 0, 1, 14 and 15 as greys (not checked in a primary document).
- MCS6500 (6 MB datasheet) and Bruce Clark's decimal mode tutorial were not read in this pass.
- Version 0.96 of *No More Secrets* could not be downloaded; 0.91 was used.

## Sources with doubtful licences

All the documentary sources (Stella Programmer's Guide, Towers' notes, 6532 datasheet, MCS6500, NMS, Horton, masswerk) lack an explicit licence in the copies consulted; they were used only to extract facts and have always been rewritten in our own words. Stella (GPL-2), Gopher2600 (GPL-3) and DASM (GPL-2+) were consulted or run without copying text or code.
