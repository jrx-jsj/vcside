## What is new

VCSIDE 0.2.0 adds a music editor, an optional AI assistant and a new set of project templates. C projects run on ELF and ACE cartridges, and the editor gets a few new tools.

### Music editor

- **Tracker and piano roll** for the same song, with instruments, patterns that each have their own speed, and a click on the piano to write the note at the cursor.
- **Tuning that knows the TIA.** Every note shows how many cents it is off, in the piano and in the grid. *Tune the song* looks for the transposition and reference pitch that put the whole song most in tune, for NTSC or PAL. The register view shows the AUDC, AUDF and AUDV each note writes.
- **Export kept up to date on save**, like the graphics: a player and data for DASM and batari Basic, sound effects included, and DPC+ and CDFJ music on those cartridges. Every song of a folder goes into one `music.asm` (or `music.h`) with one player: a new song is in the game as soon as it is saved, and `MusicPlay` with `MUSIC_SONG_<NAME>` (`music_play` in C) switches songs.
- **Samples on ELF cartridges:** several voices mixed by the cartridge's ARM, with square, triangle, sawtooth, sine, noise or drawn waveforms, envelopes and effects, plus a track and sound effects on the TIA's second channel.
- **TIA songs in C:** a TIA song can also be exported as a C player (`music.h`), for ELF games and for batari Basic's PXE kernel.
- **TIATracker songs** (`.ttt`) can be imported.

### AI assistant (optional)

- A **chat panel** that answers from VCSIDE's knowledge base and from your project: it searches the project by keywords and by meaning, and sends the open file, the selected lines and the build errors along as chips you can remove. `@` adds files and folders.
- **Local first.** A built-in helper runs a model on your computer, and VCSIDE recommends one that fits your memory and downloads it. It also finds llama.cpp, Ollama and LM Studio servers already running, or uses a model file you already have.
- **Remote services by choice** (Gemini, Anthropic, OpenAI, OpenRouter or any compatible server), with a question before the first message is sent, a token budget, and keys kept in the system's store. For now remote services work on macOS only.
- **Ask and Agent modes.** In Agent mode the assistant reads the project and proposes changes as diffs you apply one by one or all at once. Changes that would break common 2600 rules (the fire button, names that do not exist, code removed by accident) go back to the model before you see them.
- **Explain errors**: a button in the panel, or a right click in *Problems*.
- Chats are kept as tabs and open again with their service and model. A `VCSIDE.md` in the project holds notes the assistant reads first; every template has one.

### ELF and ACE cartridges

- ELF and ACE projects start empty or from *VCSIDE The Game*, with its music played as samples by the cartridge's ARM.
- `make ace` builds an ELF game as an ACE file too, from the same sources.
- C for ACE projects for the PlusCart and UnoCart, with a template, an animated sprite example and a space report. `.ace` files open as ROMs (double-click one in the project tree to run it) and run in Gopher2600, with source-level debugging. The format is in the knowledge base.
- **Serve to the PlusCart** (*Build* menu): VCSIDE answers as the cart's API host on your network, so the cart's menu lists the project's ROM, read again after every build. It has not been tried on a real cart yet.

### New projects

- **Choose the cartridge** for DASM and batari Basic projects (2K, 4K, F8, F6, F4, DPC+ and CDFJ, and PXE for batari Basic).
- **batari Basic's PXE kernel** (ZackAttack's ELF kernel): empty projects and *VCSIDE The Game*, whose music is played by C code (`pxe.c`) that VCSIDE links into the kernel after batari Basic builds the program, with the Arm GNU toolchain. PXE projects build with the PXE beta of batari Basic, which runs programs that 1.9's PXE kernel does not: unpack its release into the `bb-pxe` folder of VCSIDE's tools folder (*Settings → Tools* links to it). The Chameleon Cart image that the beta also writes has a kernel of its own, so it has no `pxe.c` and no music.
- **Two starts for every cartridge:** an empty project, or *VCSIDE The Game*, a small complete game with a title screen, a menu, enemies, collisions and music, in assembly, batari Basic, C for ELF and ACE, DPC+ and CDFJ. It can leave out the title screen, and on 2K the song too.
- **CDFJ** projects use your own copy of the CDFJ driver, chosen in *New project* or later from *Problems*: VCSIDE cannot ship it, since it has no licence that allows that.
- The dialog fits its contents, folder pickers can make a new folder on macOS, and VCSIDE remembers the folder where you made your last project.
- Opening or creating a project closes the previous one completely.

### Editor

- **Cycles or addresses:** a click on the cycle column switches every editor between each instruction's cycles and its address and size. Resting the mouse on it shows both.
- **Page and bank separators:** a red rule where a new 6502 page starts and a blue one where a new bank starts, above the `ORG` that places it. When a page starts inside an instruction, an arrow points at that line.
- **Tab size** in *View → Tab size* (4 by default), and space indentation shaded by the file's own step.
- The project tree has a context menu: open, new file or folder, rename, duplicate, delete, copy the path and show in the file manager.
- An empty editor shows the icon when every tab is closed, and pop-up menus have more room.

### Other changes

- The documentation has cards with bit tables, *See also* links and a *Recipes* branch, and its panel can be closed and opened again.
- Panels carry the three stripes beside their title.
- Fonts are made again when the window moves to a screen with a different pixel density or scaling.
- Graphics and music exports and templates are indented with tabs.
- `rem vcsgfx ... as player2` keeps a sprite up to date in a batari Basic program drawn by another player, so several enemies can share one drawing.
